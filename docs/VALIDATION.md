# 测试与本机验收

## 0.1.2 输入独占 / 输出共享回归

模式选择现在分别控制采集端和播放端：全共享为共享/共享，全独占为独占/独占，
“输入独占 / 输出共享”为独占/共享。诊断必须显示实际端点模式。混合模式下应能启动麦克风
耳返，同时让浏览器、音乐和视频播放器继续向同一个输出设备播放；输入周期按独占端协商，
输出周期按 Windows 共享引擎协商。输出仍为共享，因此不应把它描述为全链路独占延迟。

## 0.1.1 共享短队列回归

保留原有核心测试，新增四组各 120 秒模拟时长的 10 ms 块测试：
48k→48k ±500 ppm、44.1k→48k +300 ppm、48k→44.1k -300 ppm。
使用 2 ms 软件储备，检查持续输出、无欠载/重同步、排队小于 5 ms、
漂移跟踪以及断流零填充/溢出有界。启动截断计入丢弃帧，不等于运行故障。
模拟不能代替实机调度抖动或端到端延迟测量。


## 自动化测试范围

`ctest` 执行的是可重复的离线信号处理、队列和文件测试，不依赖音频硬件：

- PCM8/16/24/32/Float32 转换、24-in-32 有效位、非对齐内存和 NaN 清理。
- 平直 DSP 双声道保持、低切去直流、噪声门闭合/恢复、人声压缩、动态 EQ 有限性。
- 耳返末级限幅、静音收敛、PCM WAV 头和正常停止排空、连续启动录音。
- 有界 FIFO 满/空、顺序，以及两个线程传递 100,000 帧无错序。
- 4 段各 40 秒“模拟信号时间”的时钟漂移测试：48k→48k 的 +500/-500 ppm，44.1k→48k 的 +300 ppm，48k→44.1k 的 -300 ppm。
- 断流零填充、可观察欠载、输入超量丢弃而非无界积压。

最初控制器在 40 秒模拟中收敛偏慢；提高比例项后，上述四种条件全部通过。模拟波形时间不等于真实声卡运行时间。测试断言数也不代表同数量的独立测试场景。

GitHub Actions 应分别执行 Linux 核心测试和 Windows MSVC 编译/核心测试，并上传 Windows 便携包。Windows `--smoke-test` 仅验证启动及设备枚举路径，不打开麦克风/扬声器。Windows GUI 截图测试也不验证实际声音。

**尚须本机验证：**声卡能否支持请求周期、独占模式实际可用性、音频听感、30 分钟持续运行、热插拔、蓝牙表现以及模拟端到端延迟。不能从 CI 通过推断这些测试也通过。

## 必须执行的有线验收

先把 Windows、声卡或耳机物理旋钮音量降到安全水平。软件限幅不是听力保护，外放反馈仍可持续。

| 项目 | 操作 | 验收依据 |
|---|---|---|
| 枚举/选择 | 使用电脑自带声卡、USB 声卡（有则测）；分别选择输入输出 | 设备名称明确；缺失 ID 不自动替换 |
| 首次耳返 | 共享 / 3 ms / 1 块 / 无音效 / -18 dB | 能听到双耳人声，无明显失真；诊断有实际采样率与周期 |
| 原生同设备 | 同一声卡输入和耳机输出运行 30 分钟 | 软件排队不单向增长；应用欠载/重同步不持续增加 |
| 跨设备 | USB 麦克风 → 本地耳机，运行 30 分钟 | 时钟补偿有限、排队有界；听感稳定，否则提高缓冲 |
| 三种模式 | 分别启动全共享、全独占、输入独占/输出共享；用其他软件播放伴奏 | 全共享和混合模式可正常混音；全独占输出可阻止伴奏；诊断显示真实入/出模式 |
| 独占采样率 | 测 44.1/48/96 kHz 中设备确实支持的值 | 请求与实际格式一致；不支持则报错 |
| 降低周期 | 6 → 3 → 1.5 ms 逐档试听并导出诊断 | 记录真实周期和计数，不只记录选择框值 |
| 声道路由 | 测单声道输入、通道 2 及立体声 | 单声道双耳；单通道设备选择通道 2 时拒绝启动 |
| 快捷键 | F8、F9、Esc | 状态一致；Esc 停止并保持静音 |
| 参数调节 | 音量/EQ/音效切换，听相邻状态过渡 | 无持续爆音；大增益时末级限幅计数合理 |
| 录音 | 开始、静音、停止，随后打开 WAV | WAV 可播放；录入耳返增益/静音；停止录音不停止监听 |
| 设备热拔插 | 低音量下拔出正在使用的耳机或 USB 声卡 | 报错并停止，不改从扬声器放出，不自动恢复播放 |
| 权限/占用 | 关闭桌面麦克风权限或用其他软件独占设备 | 可理解错误消息；恢复条件后可手动重试 |
| 重新打开 | 保存后关闭、拔掉原设备再运行 | 不自动监听、不自动换输出；音量恢复上限 -12 dB |

任何一次听到刺耳反馈应立即 Esc 停止并降低物理音量。稳定优先：1.5 ms 协商成功但持续爆音不算通过。

## 端到端延迟实测方法

软件显示的“驱动报告 + 软件排队”只能帮助诊断。真正的耳返传输延迟需要比较**同一时间基准下的输入参考**与**耳机输出**。

推荐由具备接口知识的人使用额外的双通道采集设备/示波器进行低电平电气测量：将同一安全的测试信号，一路送被测输入，另一路作为测量参考；将被测耳机/线路输出经合适的衰减和阻抗匹配送测量通道 2。在一段同时采集的双通道记录中，比较同一脉冲/宽带信号两路的采样偏移，`延迟 ms = 偏移帧数 × 1000 / 测量采样率`。重复多个窗口，报告中位数和范围，并估计两路测量通道自身的偏差。

**不要把扬声器功放输出直接接入麦克风/线路输入，也不要直接用不匹配的 Y 线连接带供电/幻象供电的接口。** 没有合适设备时，先完成听感和稳定性验收；不要把估算值写成已经测得的毫秒数。

也可使用熟悉的专业 RTL 测量工具测接口自身的回环基线，但那不自动等于本程序运行链路的延迟。声学测量还包含扬声器/麦克风和空气传播影响，须在报告中说明。

建议记录：Windows 版本、CPU、设备型号、驱动版本、连接方式、模式、实际格式、实际周期、软件排队、异常计数、效果设置、测量方法、至少 10 次测量的中位数/范围。任何“低于 10 ms”的结论都应绑定这套条件，不能泛化到所有有线设备。
